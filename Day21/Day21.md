## 第二部分：阅读并修复给定错误

这些错误由课程直接提供。你负责预测、构建或分析、修复和记录，不需要自己先制造错误。

### 题1：悬空引用

```cpp
const std::string& buildMessage()
{
    std::string message{"ready"};
    return message;
}
```

回答：

1. `message`何时销毁？
2. 返回后的引用指向什么状态？
3. 当前最简单的正确返回方式是什么？

### 题2：声明与定义不一致

```cpp
// rate.h
bool setRate(int rate);
```

```cpp
// rate.cpp
int setRate(int rate)
{
    return rate;
}
```

回答：

1. 这是不是同一个函数的声明与定义？
2. 错误更可能出现在哪个阶段？
3. 如果接口语义是“设置成功或失败”，应保留哪种返回类型？

### 题3：初始化顺序

```cpp
class Packet {
public:
    explicit Packet(int payloadSize)
        : totalSize_{payloadSize_ + 4}, payloadSize_{payloadSize}
    {
    }

private:
    int totalSize_;
    int payloadSize_;
};
```

回答：

1. 哪个成员最先初始化？
2. `totalSize_`读取了什么？
3. 怎样调整声明或直接使用构造参数，使依赖关系明确？

### 题4：失败时状态被部分修改

```cpp
bool setName(std::string_view text, std::string& name)
{
    name = text;
    if (text.empty() || text.size() > 16) {
        return false;
    }
    return true;
}
```

回答：失败后`name`是否保持原值？请改成“验证全部成功后再提交修改”。

把每题的“现象、根因、最小修复”写入`assessment-notes.md`。

## 第三部分：独立实现一个配置解析模块

在`01_阶段独立实现`中完成，不复制Day20源文件。可以使用课程中已经学过的`std::string`、`std::string_view`、`enum class`、类、命名空间和多文件组织。

### 要实现的配置

```text
LogConfig
├── level       INFO / WARN / ERROR
└── flushRate   1～60秒
```

对象创建后必须合法。你可以选择合理的默认值，或者使用带参数构造函数；选择后在笔记中说明。

### 支持的命令

```text
LEVEL INFO
LEVEL WARN
LEVEL ERROR
FLUSH <1～60>
SHOW
QUIT
```

### 返回结果

解析函数不能只返回含义模糊的`false`。失败结果至少能够区分：

- 空输入；
- 未知命令；
- 缺少参数；
- 非法参数。

错误结果应包含字段和简短原因。失败时原配置必须保持不变。

### 文件结构

```text
config_parser.h
config_parser.cpp
main.cpp
assessment-notes.md
```

头文件暴露必要类型与函数，实现细节放在`.cpp`。公共头文件不使用`using namespace`，声明与定义保持同一命名空间。

### 基本测试

至少实际运行以下情况：

1. 初始`SHOW`；
2. 三种合法日志级别；
3. `FLUSH 1`和`FLUSH 60`；
4. `FLUSH 0`和`FLUSH 61`；
5. `FLUSH abc`；
6. `LEVEL`缺少参数；
7. 非法日志级别；
8. 空行与未知命令；
9. 失败后再次`SHOW`，确认原值不变；
10. `QUIT`和EOF能够正常结束。

测试不要求写成长篇文档。将关键输入、预期和实际结果简要记录到笔记即可。
